# 성능 개선 및 CI 타임아웃 해결

검증일: 2026-10-06. 구현 커밋: `a2fb85e`. 기존 실패 원인과 비용이 큰 경로를 확인하고 웹 디자인·업무 규칙·테스트 범위를 유지하며 개선했습니다.

## 원인과 변경

최근 [실패한 CI](https://github.com/yourssu/who-to-feedback/actions/runs/37414355950)는 20분 제한 초과가 아니었습니다. UI 캡처가 끝난 뒤 로그인 리다이렉트에서 `chrome-error://chromewebdata/`로 이동했고 `waitForURL`의 15초 제한으로 실패했습니다.

- UI 테스트의 가상 HTTP 응답·리다이렉트 처리를 실제 localhost Bun 서버로 바꿨습니다. 쿠키·리다이렉트·CSRF는 실제 브라우저와 서버가 처리합니다. 외부 Slack과 실제 DB는 사용하지 않습니다.
- 웹 폰트를 원래 서체의 WOFF2로 압축했습니다. 글자를 제거하지 않았고 19,810개 glyph의 윤곽·가로 폭·Unicode 매핑을 비교해 동일함을 확인했습니다. 정적 자산에 ETag와 본문 없는 304 응답을 지원하고 파일 전체를 JS 버퍼로 읽는 과정을 제거했습니다.
- 기본 결과지도 압축 폰트를 사용하고, 폰트 data URL은 프로세스에서 재사용합니다. 기존 커스텀 HTML의 `format('truetype')` 호환성을 위해 커스텀 양식은 TTF를 유지합니다.
- 매칭마다 팀원을 조회하던 반복 쿼리와 문항마다 선택지·답변을 조회하던 반복 쿼리를 묶었습니다. 매칭 조회는 인원 수와 무관하게 2번, 보고서 집계는 문항 수와 무관하게 7번 이하의 쿼리를 사용합니다. 데이터 결과를 장기 캐시하지 않아 수정한 팀원·답변이 즉시 반영됩니다.
- 발송 체크리스트는 HTML/PDF 원문 대신 존재 여부와 상태만 조회합니다. SQLite의 BLOB 길이 조회를 이용해 큰 HTML 텍스트 전체를 세거나 JS로 전달하지 않습니다.
- UI의 132개 화면 변형과 실제 임시 저장·제출 검증을 유지하면서 viewport 2개를 병렬 처리합니다. 브라우저 HTTP 캐시를 활용하고 고정 50ms 대기를 제거했습니다. 스크린샷은 애니메이션을 정지해 캡처합니다.
- UI 준비 과정의 중복 PDF 변환은 대체 어댑터로 분리했습니다. 실제 PDF 4건의 생성·한글·페이지 수 검사는 별도 `test:pdf`에서 유지합니다. 큰 화면 context JSON은 `UI_EXPORT_CONTEXT=true`일 때만 출력합니다.
- CI의 정적·업무 검사와 브라우저 검사를 병렬화하고 Chromium headless shell만 설치합니다. 다운로드 캐시를 추가하고 같은 브랜치의 오래된 실행은 취소합니다. Docker에도 headless shell만 설치합니다. Playwright 교체 없이 병목을 줄였습니다.

## 측정 결과

| 항목 | 이전 | 이후 |
|---|---:|---:|
| 원격 CI 주요 작업 시간 | 176초, 실패 | browser 59초 / checks 24초, 병렬·성공 |
| 원격 UI 단계 | 117초 후 타임아웃 | 15초, 성공 |
| 원격 실제 PDF 단계 | UI 실패로 미실행 | 6초, 성공 |
| 로컬 Docker 이미지 크기 | 약 1.89GB | 약 1.30GB (Docker inspect 기준) |
| 웹 폰트 | 15,255,648 bytes | 3,934,212 bytes, 약 74% 감소 |
| 기본 보고서 HTML 1건 | 20,409,405 bytes | 5,314,156 bytes, 약 74% 감소 |
| 로컬 HTML 보고서 3건 생성 | 약 296ms | 약 124ms |
| 로컬 체크리스트 HTTP 응답 10회 평균 | 약 18.3ms | 약 6.8ms |
| 로컬 실제 PDF 검증 4건 | 18.74초 | 11.12초 |

[성공한 GitHub Actions 실행](https://github.com/yourssu/who-to-feedback/actions/runs/37429276797)에서 실제 Linux x64 검증을 확인했습니다. 첫 실행은 브라우저 캐시가 없는 상태였습니다. CI의 초 단위 시간은 GitHub step/job 시작·종료 시각 기준이며 큐 대기는 제외합니다. 이전 UI 시간에는 실패 대기 시간이 포함됩니다.

로컬 측정은 동일한 Mac/Bun/Chromium과 `seedDemo` 예시 데이터를 사용했습니다. HTTP·HTML 측정은 메모리 DB에서 실제 앱을 호출한 결과입니다. 소규모 합성 데이터 측정이며 운영 트래픽의 응답 시간을 보장하지 않습니다. 현재 측정은 `bun run scripts/benchmark.ts`로 재현할 수 있습니다. PDF 검증 시간에는 생성뿐 아니라 Poppler 원문·페이지 검사가 포함됩니다.

## 회귀 검증과 적용 범위

- 타입·포맷 검사 및 단위·통합 테스트 60건, assertion 233건 통과
- UI 33개 화면 × 4변형, 오류 0건, 실제 로그인·임시 저장·제출 흐름 통과
- 실제 PDF 3건 각 7페이지와 긴 피드백 11페이지, 한글 원문·페이지 수 통과
- 폰트 압축본의 전체 glyph·폭·문자 매핑 비교 통과
- 100개 추가 매칭 및 100개 문항에서 쿼리 수 상한·최신 데이터·회차별 선택지 분리 검증
- 정적 폰트 304 응답과 인증 화면 `no-store` 분리 검증
- 최적화된 Linux arm64 Docker 이미지에서 실제 HTTP·PDF 3건·mock 승인/발송·재시작·DB/media 백업 검증 통과 (로컬 전체 11.83초)

웹사이트는 동일한 서체·배치를 유지합니다. 기본 보고서의 생성 HTML이 바뀌므로 기존 생성물은 자동으로 덮어쓰지 않으며 재생성하면 새 버전으로 다시 검토해야 합니다. 커스텀 양식의 TTF는 호환성을 위해 그대로 유지하므로 기본 양식과 같은 용량 감소가 적용되지는 않습니다. 원본 폰트와 압축 재현 절차는 [폰트 자산 설명](../core/static/fonts/README.md)에 있습니다.

실제 Slack 전달·Nginx·TLS·운영 트래픽 부하 시험은 이번 검증 범위에 포함하지 않았습니다.
